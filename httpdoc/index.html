A network you can draw, on one machine.

Cloonix runs virtual machines and containers on a Linux host and wires them together through Open vSwitch. You get the topology on a canvas in your browser, a root shell in any node, and a packet capture on any cable.

What it is

Two kinds of node

kvm is a QEMU/KVM machine with its own kernel. cnt is a crun container sharing the host kernel. Both take the same commands and appear the same way on the canvas.

Real switching

Links are Open vSwitch ports in a private net namespace. The packets are ethernet frames on a bridge, so routing daemons, DHCP and wifi emulation behave as they do on hardware.

Nothing installed

Cloonix ships its own QEMU, Open vSwitch, crun and passt, and loads no library from the host. The host needs none of them.

The canvas

The graphical interface is a web page served by cloonix itself. There is nothing to install on the machine you browse from.

https://127.0.0.1:4444, user nemo, password nemoclown: not secret, they are in /usr/libexec/cloonix/cloonfs/etc/cloonix.cfg, where they can be changed.

The items, and how they cable together

An item owns one or more ports. Each port carries one connection, drawn as a line to a crossroad called a lan — which is an Open vSwitch bridge. Everything on this list plugs into everything else the same way.

What you do with it

Test routing

Sixty FRR routers in a spider topology start in about a minute. Watch OSPF converge, cut a cable, watch it reconverge.

Read the wire

Double-click a green interface dot to capture it. The dissection engine is wireshark's, the viewer is a web page — no Qt, no X forwarding.

Reproduce a bug

A topology is a python file of a few lines. Send it to somebody and they get the same network.

Or learn what a network does

demos/ holds subject areas, and under each one python file per demo: a running topology, every cloonix command printed as it is typed, and the packet that shows the protocol at work.

What you can learn

Two ways to install

The toy

A tarball you extract as a normal user. Cloonix runs inside a container it brings with it. No root, nothing written outside the directory, and deleting the directory removes it.

Everything on this page works in the toy.

The bundle

An installation under /usr/libexec/cloonix, done once as root. Several users share it, each running their own networks.

One installation serves every user of the machine.
